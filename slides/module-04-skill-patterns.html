The Hierarchy

Marketplace          ← a catalog (one GitHub repo) listing plugins
  └── Plugin         ← the shareable bundle you install
        ├── Commands ← slash-command skills (/check-style)
        ├── Skills   ← auto-invoked SKILL.md skills
        ├── Agents   ← subagents with own prompt & tools
        ├── Hooks    ← event handlers
        └── MCP servers
A marketplace contains plugins. A plugin bundles commands, skills & agents.

Command vs. Skill vs. Agent vs. Hook

All four are "instructions Claude Code follows" — they differ in who triggers them and how much isolation they get.

  • Command — runs when you type /name. Everything you built in Module 3.
  • Skill — a SKILL.md with a description, so Claude can auto-invoke it too.
  • Agent — an isolated worker with its own tools & model, for delegated multi-step jobs.
  • Hook — a shell command that fires automatically on an event. No reasoning, never skipped.
We'll build one small example of each — using the same style-check task — so you can see all four side by side.

Example: Command vs. Skill

Command — commands/check-style.md — runs only when typed:

You are a technical editor. Review: $ARGUMENTS

Check for active voice, sentences <25 words,
sentence-case headings.

Output a table: Line | Issue | Fix

Usage: /check-style docs/orders-api.md

Skill — skills/doc-coverage/SKILL.md — same idea, plus a description Claude reads to auto-invoke it:

---
name: doc-coverage
description: Use when a code change might need
  matching documentation updates.
---
Compare the diff at $ARGUMENTS against docs/...
8 / 18

Example: Agent vs. Hook

Agent — agents/doc-auditor.md — its own context, tools & model, for multi-file jobs:

---
name: doc-auditor
description: Audits an entire docs set. Use for
  multi-file jobs, not single-file checks.
tools: Read, Grep, Glob
model: sonnet
---
Read every file in the folder, apply style +
completeness rules, return one ranked report.

Usage: "Use the doc-auditor agent to review everything in docs/." Only the final report returns to your conversation.

Hook — hooks/hooks.json — fires on every edit, no prompt involved:

{ "hooks": { "PostToolUse": [{ "matcher": "Edit|Write",
  "hooks": [{ "type": "command",
    "command": "echo 'Reminder: run /check-style'" }] }] } }

How the Four Connect

Triggered byIsolationBest for
HookAn event (edit, commit, session end)None — just runs a commandRules that must always fire
CommandYou, typing /nameYour current conversationA check you consciously run
SkillYou, or Claude automaticallyYour current conversation"Whenever a request looks like X..."
AgentYou, or Claude delegatingIts own context windowA multi-step job too big to run inline
Hook nudges you → Command/Skill checks one file → Agent handles the full sweep. All four ship inside one plugin, distributed by a marketplace.

Namespacing prevents collisions — bundled in the doc-skills plugin, check-style runs as:

/doc-skills:check-style

Installing — Step 1: Add the Marketplace

/plugin marketplace add AmanProjects/twtai-skill

→ Successfully added marketplace: twtai

Also accepts:

  • owner/repo@v1.0 (branch or tag)
  • a git URL (GitLab, etc.)
  • ./local-folder
A marketplace is just a GitHub repo with a marketplace.json catalog.
11 / 18

Installing — Step 2: Install the Plugin

/plugin install doc-skills@twtai
twtai is the marketplace name, not the repo (twtai-skill).

Step 3 — use it:

/doc-skills:check-style sample-docs/orders-api.md

Or run /plugin → Discover tab → pick → scope (User / Project / Local).

Manage: /plugin list, /plugin disable, /plugin uninstall.

The Two Files That Make It Work

marketplace.json (repo root, in .claude-plugin/) — the catalog:

{
  "name": "twtai",
  "owner": { "name": "Tech Writer's Tribe" },
  "plugins": [
    { "name": "doc-skills", "source": "./plugins/doc-skills",
      "description": "Docs skills from the TWT program." }
  ]
}

plugin.json (in the plugin's .claude-plugin/) — the manifest:

{ "name": "doc-skills", "version": "1.0.0",
  "description": "Documentation skills." }
Only these two go in .claude-plugin/. commands/, skills/, agents/ sit at the plugin root.

Workshop: Publish Your Own

Work in pairs — one publishes, one installs, then switch.

The 5-step loop:

  1. Create a GitHub repo (your-name/my-skills)
  2. Add .claude-plugin/marketplace.json (pick a name)
  3. Add a plugin folder with plugin.json + your skill in commands/
  4. Commit & push
  5. Share two lines:

```

/plugin marketplace add your-name/my-skills

/plugin install my-plugin@my-marketplace

```

Start from the twtai-skill template — don't build from a blank repo.

When a Marketplace Is Overkill

SituationLightweight option
One skill, one person, onceSend the .md; they drop it in .claude/commands/
Your project teamCommit .claude/commands/*.md into the project repo
Connect to a hosted toolCommit a project .mcp.json with a remote URL

Use a marketplace for versioning, many skills, auto-updates, and one-command install at scale.
