  flags long sentences, passive voice, Title Case headings.

---
Read the file. Call word_stats. Output a table.

A worked example lives at
${CLAUDE_PLUGIN_ROOT}/skills/readability-pass/reference.md.
Read it only when the user asks what "good" looks like.

Progressive disclosure — reference.md costs nothing until read.

The description is a routing decision, not a summary. Write when to use this.

2. Commands — and the Name Trap

---
description: Print a health summary for a docs folder.
argument-hint: <folder>
disable-model-invocation: true
---
Produce a health summary for: $ARGUMENTS

Flat .md, no folder. disable-model-invocation = Claude never fires it alone.

⚠️ Single-skill plugin? Put SKILL.md at the root and set name: in frontmatter.

Without it, the name falls back to the install directory — which for marketplace installs is a version string that changes on every update.

3. Agents

---
name: doc-auditor
description: Audits an entire documentation set. Multi-file sweeps.
model: sonnet
effort: medium
maxTurns: 20
tools: Read, Grep, Glob
disallowedTools: Write, Edit
skills: readability-pass
memory: false
background: false
---

Also: isolation — the only valid value is "worktree".

🔒 Plugin agents may not declare hooks, mcpServers, or permissionMode.

Invoke as @doc-toolkit:doc-auditor.

4. Hooks — The Scoped-Name Trap

To hook your own bundled MCP server, you must use the scoped name.

✅  "matcher": "mcp__plugin_doc-toolkit_docstats__word_stats"
❌  "matcher": "docstats"        ← silently never fires
FieldFormat
Tool matcher / ifmcp__plugin_<plugin>_<server>__<tool>
mcp_tool hook's serverplugin:<plugin>:<server>
A matcher against the bare server key never fires — and never errors.

5. MCP Servers

{
  "mcpServers": {
    "docstats": {
      "command": "node",
      "args": ["${CLAUDE_PLUGIN_ROOT}/mcp/docstats-server.js"],
      "env": { "CACHE_DIR": "${CLAUDE_PLUGIN_DATA}/cache" }
    },
    "team-docs-api": {
      "type": "http",
      "url": "https://example.com/mcp"
    }
  }
}

Our bundled server is dependency-free on purpose — raw JSON-RPC, no npm install.

Whatever you bundle must start on a teammate's machine the second they enable it.

6. LSP Servers

{
  "markdown-docs": {
    "command": "node",
    "args": ["${CLAUDE_PLUGIN_ROOT}/lsp/markdown-server.js"],
    "extensionToLanguage": { ".md": "markdown" },
    "startupTimeout": 5000,
    "restartOnCrash": true,
    "diagnostics": true
  }
}

Required: command, extensionToLanguage. Everything else optional.

  1. You install the binary separately — the plugin only configures the connection
  2. First registration wins per extension; the other server never starts
  3. A bad config is skipped silently — claude --debug tells you why

7. Monitors  ·  8. Workflows

[
  { "name": "docs-build",
    "command": "\"${CLAUDE_PLUGIN_ROOT}\"/scripts/poll-build.sh",
    "description": "Docs site build status changes",
    "when": "always" },
  { "name": "audit-log",
    "command": "tail -F ./logs/doc-audit.log",
    "description": "Streams the doc audit log",
    "when": "on-skill-invoke:readability-pass" }
]

Every stdout line reaches Claude as a notification. Interactive CLI only · unsandboxed · no ${user_config.*} · not loaded for project-scope skills-dir plugins.

Workflows — deterministic multi-agent scripts. pipeline() by default; parallel() only when a stage needs all prior results.

The Manifest Is Optional

Drop components in default folders → Claude Code finds them. Name = directory name.

Write a plugin.json when you need metadata, custom paths, or user config.

{
  "name": "doc-toolkit",              ← the ONLY required field
  "displayName": "Docs Toolkit",
  "version": "1.0.0",
  "description": "…",
  "author": { "name": "…", "email": "…", "url": "…" },
  "homepage": "…", "repository": "…", "license": "MIT",
  "keywords": ["documentation"],
  "metadata": { "anything": "you want" },
  "defaultEnabled": true,
  "userConfig": { }, "channels": [ ], "dependencies": [ ]
}

name is kebab-case and namespaces everything: doc-toolkit:doc-auditor.

19 / 32

Three Manifest Surprises

1. Unknown top-level fields are ignored, not fatal. Keep VS Code / npm / MCPB metadata in the same file. validate warns and suggests near-miss corrections.

2. Wrong types usually are fatal. "keywords": "docs" is a load error. Exceptions: experimental and metadata — ignored with a warning.

3. Path fields don't behave the same way:

BehaviorFields
Replaces the default foldercommands, agents, workflows, outputStyles, experimental.*
Adds to the defaultskills — skills/ is always scanned
Own merge ruleshooks, mcpServers, lspServers
"commands": ["./extras/"]                ← commands/ no longer scanned!
"commands": ["./commands/", "./extras/"] ← keep both

userConfig — Ask, Don't Make Them Edit JSON

"userConfig": {
  "max_sentence_words": {
    "type": "number", "title": "Max sentence length",
    "description": "Flag sentences longer than this.",
    "default": 25, "min": 10, "max": 60
  },
  "docs_api_token": {
    "type": "string", "title": "Docs API token",
    "description": "Stored in the OS keychain.",
    "sensitive": true
  }
}

Types: string · number · boolean · directory · file.
Options: sensitive · required · default · multiple · min/max.

Where userConfig Values Appear

SurfaceHow
Skill & agent content${user_config.KEY} — non-sensitive only

Anything running through a shell rejects ${user_config.*} — the shell would execute whatever the value contains.

Shell-form hooks → use exec form with args, or read the env var.

Sensitive → OS Keychain (~2 KB shared). Project settings are ignored for pluginConfigs — a cloned repo must not feed your hooks.

Caching, Versioning, Debugging

Marketplace plugins are copied to ~/.claude/plugins/cache, one dir per version.

→ ../shared-utils will not work after install. Symlinks: inside the plugin are preserved, elsewhere in the marketplace are dereferenced, outside are skipped.

The One Structural Rule

Only plugin.json goes in .claude-plugin/. Everything else lives at the plugin root.
SymptomFix
Plugin doesn't loadclaude plugin validate ./my-plugin
Skills missingskills/ at the root, not in .claude-plugin/
Hooks don't firechmod +x script.sh
Hooks don't fire on MCP toolsUse the scoped mcp__plugin_… name
MCP server failsUse ${CLAUDE_PLUGIN_ROOT}, not a hardcoded path
LSP not found in $PATHInstall the language server binary

A CLAUDE.md at the plugin root is not loaded as context — ship instructions as a skill.

2026: Agent Plugins v1.0.0

Every agent client grew its own plugin format. A skill written for one didn't load in another.

"A portable package format for Agent Skills and MCP servers."

Drafted by Vercel, refined by a working group with AWS, Cursor, Microsoft, OpenAI.

Launch clients: ChatGPT · Codex · Cursor · GitHub Copilot · Kiro · VS Code

Spec CC-BY-4.0 · code Apache-2.0 · Technical Steering Committee

MCP standardized tools. Agent Skills standardized SKILL.md.
Agent Plugins standardizes the package that carries them.
28 / 32

Two Component Types. That's It.

ComponentFixed locationPattern
Skillsskills/Immediate subdirs containing SKILL.md
MCP serversmcp.jsonJSON configuration

Commands, hooks, agents, rules, LSP servers were all considered and deliberately excluded — the spec calls them "too client-specific for a stable portable contract."

Skills and MCP made the cut because both already had independent specs and real cross-client adoption.

Locations are fixed and cannot be overridden. No custom paths, no inline MCP config.

⚠️ Anthropic is not on the maintainer list. Two formats today — learn both.

The Portable Manifest — Closed Schema

{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "portable-doc-toolkit",
  "version": "1.0.0",
  "description": "…", "author": { }, "homepage": "…",
  "repository": "…", "license": "MIT", "keywords": [ ],
  "extensions": { "com.anthropic.claude-code": { } }
}

Exactly ten fields are permitted — the inverse of Claude Code, where unknown fields are simply ignored.

$schema and name required. Clients must not fetch the schema at load time.

name: 1–64 chars, a-z 0-9 - ., alphanumeric ends, no -- or ..

Broken manifest = fatal. Broken component = never fatal.
30 / 32

mcp.json — Explicit Transports

{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
  "mcpServers": {
    "docstats": {
      "type": "stdio",
      "command": "node",
      "args": ["${PLUGIN_ROOT}/mcp/docstats-server.js"],
      "cwd": "${PLUGIN_ROOT}",
      "env": { "CACHE_DIR": "${PLUGIN_DATA}/cache" }
    }
  }
}
  • command is one executable token, never a shell string — no expansion
  • Only ${PLUGIN_ROOT} / ${PLUGIN_DATA} expand, in args, env, cwd
  • Paths start ./ and must stay inside the plugin root
  • Remote url: absolute HTTPS (loopback may use HTTP) · no secrets in headers or env

🟠 Workshop & Checkpoint

Build a three-component plugin — one skill, one hook, one tool. Nothing else.

claude plugin init <you>-toolkit --with skills hooks mcp
claude plugin validate ~/.claude/skills/<you>-toolkit --strict
claude plugin details <you>-toolkit
  • Name all thirteen components and their default locations
  • Say which cost tokens in every session — and check it
  • Write a hook matcher that fires on a bundled MCP tool
  • Choose between PLUGIN_ROOT and PLUGIN_DATA correctly
  • Say which path fields replace the default folder
  • Port a plugin to Agent Plugins v1.0.0 without breaking it
"A plugin is a budget, not a bucket. Every component is a tax on every session — ship the three that earn it."
