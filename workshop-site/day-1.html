Day 1—AI literacy for technical writers

Novice Module 1 2 hours No prerequisites Web-friendly
Full lesson

This page is the workshop summary and agenda. For the complete lesson text, open the Module 1 lesson.

Overview

Build confidence before building anything

The first session removes the mystery. You will learn how large language models work using a plain analogy, see clearly what AI does well and where it needs your judgment, and complete real documentation tasks with Claude so that by the end you have already done the thing that felt intimidating an hour earlier.

You can do this whole day in the browser

Everything in day 1 works in the Claude.ai web interface. Sign in, start a chat or a Project, and you are ready—no installation, no API key.

Learning objectives

By the end of this day you can

  • Explain how LLMs work using a simple analogy, no math required.
  • Name three things AI does well and three things it needs human judgment for.
  • Describe the human + AI partnership model in your own words.
  • Complete at least one real documentation task using Claude.

Agenda

Two-hour flow

  • 0:00–0:15
    Welcome and framing
    The five skill tiers, how the two tracks work, and what you will leave with.
  • 0:15–0:45
    How LLMs work—the library analogy
    Prediction, context, and key vocabulary—tokens, context window, hallucination—in writer's terms.
  • 0:45–1:05
    Strengths, limits, and the partnership model
    What AI is good at, what it needs you for, and the amplification model.
  • 1:05–1:45
    Three live exercises
    Ask Claude about your work, give it a real documentation task, and run the quality safety net.
  • 1:45–2:00
    Discussion, takeaway, and homework
    Reflection questions and the one key idea to carry forward.

Activities

Three confidence builders

  1. Ask Claude about your work

    Open Claude and ask it to find the structural problems in a sample API document. You are evaluating its reasoning, not trusting it blindly.

  2. Give Claude a documentation task

    Paste one of your own documents and ask for structured feedback: what works, what is unclear, and three specific improvements.

  3. Run the quality safety net

    Run a six-point completeness check against sample-project/test-docs/bad-api-doc.md and read the gaps it surfaces.

Doing it on the web

Claude.ai web alternatives

The lesson references opening "claude.ai or Claude Code." Here is the mapping for this day.

Claude Code (as written)

Launch claude in a terminal inside the repo and paste the prompt, referencing files by path such as sample-project/test-docs/bad-api-doc.md.

Claude.ai web interface

Start a new chat, drag the sample document into the message (or upload it), and paste the same prompt. For the completeness check, keep it in a Project so the six-point checklist lives in the custom instructions and applies to every chat.

Tip

Save the completeness-check prompt as a Project custom instruction now. In day 3 you will turn it into a reusable Skill—this is the same idea, one step earlier.

Homework

Before day 2

  • Run the completeness check on one real document from your own work and note what it caught that you would have missed.
  • Write down three documentation tasks you do repeatedly—you will use them in day 2.

Checklist

Novice checklist

  • I can explain an LLM to a colleague without using the word "magic".
  • I completed at least one documentation task with Claude.
  • I have a Claude account I can sign in to.
