Using the Claude.ai web interface

No install No API key Projects · Skills · Connectors

Why this page exists

The course was written for Claude Code—you can do most of it in a browser

The lessons assume Claude Code, the command-line tool. But the writing, reviewing, and skill-building that make up days 1 through 5 can be done entirely in the Claude.ai web interface, through three features: Projects, custom Skills, and Connectors. This page maps the command-line world onto the browser and is honest about where the browser stops.

The short version

Days 1–3 are fully web-friendly. Day 5 is partly web-friendly through Connectors. Days 4, 6, and 8—plugins, local MCP servers, and plugin authoring—need Claude Code or Claude Desktop. Day 7 publishes from the browser.

The three features

What the browser gives you

Projects

A persistent workspace that groups related chats with shared custom instructions and uploaded knowledge files. This is where a repeatable prompt and your reference docs live so every chat in the project starts with the same context.

Skills

Reusable instruction sets Claude loads on demand. Create them under Customize → Skills: write the instructions, upload a SKILL.md, or let Claude build one from a description. This is the browser's version of a slash-command skill.

Connectors

MCP servers, surfaced in the browser. Enable a remote connector—an issue tracker, a knowledge base, calendars—so Claude can read from and act in external systems without any configuration file.

Step by step

Create your first Skill in the browser

  1. Open Customize → Skills

    From the Claude.ai interface, open Customize and find Skills. Custom Skills require code execution and file creation to be enabled, on Pro, Max, Team, or Enterprise plans.

  2. Add a Skill

    Choose to write the instructions directly, upload a finished SKILL.md, or pick Create with Claude and describe the task so Claude writes it for you.

  3. Write a good description

    The description tells Claude when to load the Skill. Make it specific—"review API reference docs for completeness" beats "doc helper".

  4. Use it

    Claude loads the Skill automatically when a request matches, or you can name it. Test it on a real document and iterate, exactly as in day 3.

Step by step

Set up a Project for a documentation workflow

  1. Create a Project

    Name it for the workflow—for example, "API reference review".

  2. Add custom instructions

    Paste your RTCCO prompt as the project's standing instructions so every chat starts with the right role, task, and output format.

  3. Upload knowledge files

    Add your style guide and a known-good example doc. Claude treats them as persistent context across every chat in the project.

  4. Work in chats

    Drop a draft into a new chat and ask for the review. The project context does the rest.

Honest limits

What genuinely needs the command line

Claude Code or Claude Desktop only

Three things in this course have no browser equivalent today: installing and publishing plugins and marketplaces (day 4 and day 8), building and running a local MCP server of your own (day 6), and writing an LSP language server (day 7 bonus). For a whole team, the nearest web-native substitute for a plugin is an organization-provisioned Skill that a Team or Enterprise admin publishes once for everyone.
