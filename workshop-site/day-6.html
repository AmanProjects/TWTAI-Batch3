Day 6—Building MCP tools: extending a real server

Advanced Module 6 2 hours TypeScript Claude Code / Desktop
Full lesson

This page is the workshop summary and agenda. For the complete lesson text, open the Module 6 lesson.

Overview

Read, extend, and publish a documentation-quality server

Day 6 crosses from using tools to building them. You will read a real TypeScript MCP server in plain language, add a new tool to it, expose your style guide as a resource, connect it to Claude, and optionally publish it to the registry. The lesson is deliberately readable even if you have never written TypeScript.

This day needs a local environment

Building and running a local MCP server requires Claude Code or Claude Desktop plus Node.js. It cannot be done in the browser. Writers who want the concept without the code should follow the no-code path below.

Learning objectives

By the end of this day you can

  • Read and explain TypeScript MCP server code in plain language.
  • Add a new tool to an existing MCP server.
  • Expose a resource—such as your style guide—through an MCP server.
  • Connect your MCP server to Claude and verify it works.

Agenda

Two-hour flow

  • 0:00–0:20
    Explore the starter project
    Read package.json and the server source without panicking about TypeScript.
  • 0:20–0:50
    Add a new tool—live exercise
    Add a grade_readability tool, then build and test.
  • 0:50–1:15
    Connect to Claude
    Register the server and verify the new tool appears.
  • 1:15–1:40
    Shortcut: scaffold with the MCP builder
    When to hand-write and when to let the builder generate the skeleton.
  • 1:40–2:00
    Publish and wrap-up
    Optional: publish to the official registry or npm.

Two paths

Engineering build or no-code understanding

Engineering track

Build it

Read sample-project/src/index.ts, add the grade_readability tool, run npm run build, register with claude mcp add doc-quality-checker, and verify with /mcp. Optionally rebuild as style-guide-enforcer and publish.

Writers' track

Understand it

You do not need to write TypeScript to benefit. Focus on what a tool and a resource are, read the server with Claude explaining each section, and connect a ready-made documentation server as a Connector instead of building one.

Doing it on the web

Claude.ai web alternatives

Claude Code (as written)

Edit the server, npm run build, then claude mcp add doc-quality-checker -- node dist/index.js and confirm with /mcp.

Claude.ai web interface

Use the browser to understand and draft the code—paste the server source and ask Claude to explain it, or to write the new tool for you to copy into your editor. Running the local server still needs Claude Desktop or Claude Code. Published remote servers can later be added as Connectors.

Homework

Before day 7

  • Expose your own style guide as a resource through the server, or connect a ready-made documentation server and use it in a skill.
  • Bring a résumé—PDF, Word, or plain text—for the day-7 capstone.

Checklist

Advanced checklist

  • I can explain what the server does, section by section.
  • I added a tool, or I connected and used a ready-made server.
  • I verified the tool is available to Claude.
