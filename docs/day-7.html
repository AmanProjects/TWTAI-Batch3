Day 7—Capstone: your portfolio site from a résumé

Advanced · upper Module 7 2 hours Two tracks Publishes to the web
Full lesson

This page is the workshop summary and agenda. For the complete lesson text, open the engineering track lesson or the writers' track lesson.

Overview

Put every piece together into something public

The capstone assembles the whole mental model—skill, agent, plugin, MCP server—into one project. You will turn your résumé into structured data, direct an agent to build a portfolio site from it, review the result like an editor, and deploy it to a public URL. This day runs as two parallel tracks so non-coders ship the same site without writing HTML.

Choose your track

Writers' track and engineering track

Writers' track · primary

Single-sourced, no code

You will not write HTML, CSS, JavaScript, or a language server. You turn your résumé into resume.json, brief the portfolio-builder agent, review its work, and publish through the browser—updating the whole site later by changing one file.

Engineering track · optional depth

Full build

You write the static site by hand, build the agent, add an about-me MCP server others can install, and build a documentation language server—the fifth extension mechanism and the only one that is not Claude-specific.

Learning objectives

By the end of this day you can

  • Explain the complete mental model—when to reach for a skill, an agent, a plugin, or an MCP server, and how they compose.
  • Turn a résumé into structured resume.json using the JSON Resume schema.
  • Direct an agent to build a complete portfolio site from that data, reviewing its work rather than writing it.
  • Deploy to the web and get a public URL.
  • Update the site later by changing one file.
  • Write a CLAUDE.md so Claude follows your conventions in every session.

Agenda

Two-hour flow

  • 0:00–0:15
    The five building blocks
    The complete mental model and the decision that trips everyone up.
  • 0:15–0:40
    Your résumé becomes data
    Create the /parse-resume skill, then do the part only you can do—edit the data for truth and emphasis.
  • 0:40–1:15
    Direct the agent to build the site
    Create portfolio-builder, run it, preview, and review it like an editor.
  • 1:15–1:45
    Publish
    Browser-only route, or let Claude do it; turn on GitHub Pages.
  • 1:45–2:00
    CLAUDE.md and wrap-up
    Capture your conventions; optional LSP and about-me tracks for engineers.

Doing it on the web

Claude.ai web alternatives

Claude Code (as written)

Preview with python3 -m http.server, deploy with git or the gh CLI, and optionally add an about-me MCP server and a docs-lsp language server.

Claude.ai web interface

Generate the site as an Artifact in a chat and preview it right there. Parse the résumé with a Skill. Publish using the browser-only route the writers' track already uses: create the GitHub repo and turn on Pages entirely in the browser—no command line. The LSP and about-me MCP server remain engineering-track, local-environment work.

The writers' publish route is already web-native

Route A in the lesson is browser-only by design. If you have been on the web interface the whole course, this is the day it pays off—you ship a live site without ever opening a terminal.

Homework

Before day 8

  • Polish your live site and share the URL with a peer for feedback.
  • Run the docs-lsp link checker on a real set of your docs and fix what it finds (both tracks).

Checklist

Advanced checklist

  • My portfolio site is live at a public URL.
  • I can update it by editing one data file.
  • I wrote a CLAUDE.md that captures my conventions.
